# Project Overview

The team immediately began brainstorming, prioritizing quantity over quality to ensure a wide range of creative possibilities. We are using Discord as our primary communication hub, specifically utilizing the Threads feature to organize discussions. Each new idea is given its own thread to keep the conversation focused and structured.

## Brainstorming Rules

To maintain productivity, we have established the following guidelines:

1. **Focus:** No suggesting alternative ideas within a specific idea's thread.
2. **No Tangents:** Side topics and branching conversations are strictly prohibited.
3. **Constructive Critique:** Do not point out flaws simply to dismiss an idea. Instead, frame them as challenges to be solved. Our current goal is to diversify and support ideas; the elimination phase begins next week.
4. **Professionalism:** No joking or sarcasm within threads. The environment must remain serious, ensuring every message adds value.

## Meeting Management & Documentation

In the early stages, we faced scheduling conflicts that made full-team attendance difficult. To resolve this, we are testing a new "Session" method:

- **Meeting Logs:** If a member is absent, a designated note-taker records all key ideas, questions, and discussions.
- **Documentation:** These logs are posted in a dedicated "Sessions" channel on Discord to keep everyone updated.

## Team Integration & Peer Learning

To strengthen team cohesion, every member has filled out a profile in a `team_info.md` file within our GitHub repository.

Furthermore, we are leveraging GitHub for Peer Learning:

- **Code Reviews:** We use Pull Requests (PRs) to discuss code logic and clarify complex segments.
- **Knowledge Sharing:** We hold "Mini-Sessions" where a team member teaches a specific concept, framework, or piece of code they have mastered to ensure the entire team grows together.

## Task Tracking & Tools

While we currently use Notion for task management, we are evaluating GitHub Projects as a potential replacement to consolidate our workflow within a single platform.

### Core Tools

- **Discord:** Communication & Brainstorming.
- **Notion / GitHub Projects:** Task Tracking.
- **GitHub:** Version Control & Peer Learning.

### Summary

A hybrid social networking platform that merges the community-driven discussion model of Reddit with the professional identity and "CV-style" profile system of LinkedIn. It is designed to foster high-level technical discourse while allowing contributors to build a public professional reputation.

### Target Audience

# MVP Documentation: Project-Based Educational Marketplace

## 1. Project Overview & Vision

The goal of this platform is to bridge the gap between passive video-based learning and rigorous, industry-standard engineering training. By adopting the Holberton School methodology—which emphasizes project-based learning, peer interaction, and automated feedback—and merging it with the Udemy marketplace model, we enable experts to create, share, and monetize deep-learning technical curricula.

## 2. Problem Statement

- **The "Tutorial Hell" Trap:** Most e-learning platforms focus on passive watching. Students often finish courses without being able to write code from scratch.
- **Grading Bottlenecks:** Rigorous, high-pressure education usually requires manual grading, which is expensive and difficult to scale.
- **Lack of Structure:** Self-paced learners often struggle with a lack of deadlines and structured "Sprints," leading to high abandonment rates.

## 3. MVP Core Feature Specifications

### 3.1 The Automated Validator (The Checker)

The "Checker" is the engine that enforces quality. It provides instant feedback, ensuring students meet both functional and structural requirements before moving forward.

- **Execution Engine:** Full integration with Judge0 for secure, isolated code execution across multiple languages.
- **Multi-Layered Validation:**
  - **Functional (I/O Testing):** Ensures the code produces the correct results for given inputs.
  - **Reliability (Unit Testing):** Forces the code to handle complex edge cases.
  - **Structural Analysis (AST):** Uses Abstract Syntax Tree libraries to inspect the code's logic. This allows the system to enforce constraints such as forbidding specific loops or requiring certain architectural patterns (e.g., recursion or specific data structures).
  - **Standardization:** Built-in linting checks to maintain industry-standard formatting.
- **Extensibility:**
  - **Default Mode:** Initial launch support optimized for C.
  - **Custom Mode:** Tools for advanced creators to upload proprietary test suites.

### 3.2 User Dashboard

A dynamic control center designed to reduce cognitive load and keep students focused on immediate goals.

- **Live Tracking:** Visual representation of progress within the current Sprint.
- **Communication Layer:** Direct-to-creator messaging system for technical support.
- **Deadline Management:** Clear countdowns and task prioritization to simulate real-world work environments.

### 3.3 Curriculum Designer (Creator Suite)

A professional workspace for "Curriculum Architects" to design the learning experience.

- **Complexity Mapping:** An intuitive interface to break down subjects into Sprints, Projects, and granular Tasks.
- **Instructional UX:** A guided flow to help creators set up dependencies and automated test cases without needing to build their own infrastructure.

### 3.4 Curriculum Browser

A marketplace entry point designed for high-intent discovery.

- **Marketplace Logic:** A rating and review system that allows the community to identify the most effective and rigorous curricula.
- **Discovery Tools:** Filtering by technical stack (e.g., C, Python, JavaScript), difficulty, and peer engagement metrics.

## 4. Technical Implementation Strategy

| Component | Technical Approach |
|-----------|-------------------|
| Backend Architecture | Node.js/Express with PostgreSQL for robust data dependency management. |
| Code Execution | Isolated Judge0 instances to prevent security breaches during execution. |
| Code Inspection | Custom AST parsing logic to grade "Code Quality" and "Logic Path" automatically. |
| Frontend | React-based dashboard optimized for real-time state updates. |

## 5. Strategic Evaluation (MVP Selection)

The decision to move forward with this MVP was based on a weighted ranking of its potential within the current market:

| Criteria | Score |
|----------|:-----:|
| Feasibility | 1 |
| Potential Impact | 1 |
| Technical Alignment | 1 |
| Scalability | 1 |
| Constraints | 1 |
| Risks | 1 |
| **Final Rank** | **6 / 6** |

**Technical Advantage:** By utilizing AST analysis, the platform offers a unique competitive edge: it does not just check if code works; it checks if the code is well-written. This creates a standard of excellence that distinguishes our graduates and our creators' content from standard "low-friction" e-learning platforms.
